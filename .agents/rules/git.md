# Git 작업 규칙

## 핵심 규칙

- **브랜치:** 대상은 저장소의 실제 기본 브랜치나 사용자가 지정한 브랜치를 확인한다. 새 브랜치는 기본적으로 `codex/<영문 설명>`을 사용하고, 사용자 지정이 있으면 따른다.
- **제목:** 커밋과 PR/MR은 `type: <한국어 변경 요약>`으로 쓴다. 타입은 [릴리스 분류](release.md)를 따르고, 끝 마침표는 넣지 않는다.
- **커밋:** 하나의 목적만 담고, 사용자가 요청한 커밋 분리를 유지한다. 본문은 필요한 설명만 쓴다.
- **이슈:** 연결된 이슈가 있을 때만 실제 키·번호와 링크를 제목 또는 본문에 넣는다. 티켓을 추정하거나 만들어 넣지 않는다.
- **호환성 깨짐:** 제목에 `type!:`, 본문에 `BREAKING CHANGE: <영향과 전환 방법>`을 쓴다.
- 기존 사용자 변경을 보존하고, 작업 범위 밖의 파일을 커밋에 섞지 않는다.

## 커밋 예시

| 타입 | 제목 예시 |
| --- | --- |
| feat | feat: 도메인 규칙 검증 추가 |
| fix | fix: 잘못된 상태 변경 차단 |
| refactor | refactor: 도메인 계산 로직 정리 |
| docs | docs: 프로젝트 실행 방법 추가 |
| chore | chore: 공용 에이전트 지침 정리 |

기능 추가 타입은 `feature`가 아닌 `feat`를 쓴다.

## PR/MR 본문

- 최종 변경의 문제와 결과를 짧게 설명한다. 변경 내용은 핵심 1~3개 항목으로 쓴다.
- 작업 과정·파일별 나열·중복 설명은 생략한다.
- 검증에는 실제 실행한 검사와 결과, 미실행 검사가 있으면 그 이유를 적는다.
- 관련 이슈·배포 주의사항은 있을 때만 추가한다. 본문 전체를 코드 블록으로 감싸지 않는다.
