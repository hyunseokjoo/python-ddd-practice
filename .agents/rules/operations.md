# 빌드·문서 규칙

## 포맷·정적 분석·테스트

- 편집기에서 [.editorconfig](../../.editorconfig) 지원을 활성화한다. `max_line_length` 지원 여부는 편집기에 따라 다르며, 이 파일만으로 포맷·린트 검사가 실행되지는 않는다.
- Python 포맷터·린터를 도입할 때는 Ruff를 우선한다. Ruff는 `.editorconfig`를 읽지 않으므로 실제 도입 시 별도 설정의 줄 길이를 맞춘다. Black과 Ruff 포맷터를 함께 실행하지 않는다.
- 정적 타입 검사가 필요하면 mypy 또는 Pyright 중 하나를 사용한다. Ruff는 타입 검사기를 대신하지 않는다.
- 저장소에 실제로 설정된 도구와 명령을 사용한다. 설정 파일·의존성·CI를 확인한 뒤 실행한다.
- 도구가 아직 설정되지 않았다면 미설정이라고 알린다. 존재하지 않는 명령을 실행 방법으로 기록하지 않는다.
- 변경에 해당하는 검사부터 실행하고, 실패나 영향 범위가 요구할 때만 검증 범위를 넓힌다.
- 검사를 통과시키려고 검증을 끄거나 가짜 기본값을 넣지 않는다.

## 빌드·실행

- 의존성을 추가할 때는 저장소의 의존성 관리 방식과 잠금 파일을 따른다.
- 컨테이너를 도입하면 네이티브 의존성과 베이스 이미지의 호환성을 확인한다.
- 임시 파일은 표준 라이브러리 tempfile을 사용한다. 영속 데이터는 명시한 저장 경로와 쓰기 권한을 확인한다.
- 시크릿은 저장소에 커밋하지 않는다. 필수 설정 누락은 명확한 오류로 알린다.

## 문서

- README에는 검증된 사실만 적는다. 실행하지 않은 명령을 검증됐다고 쓰거나 존재하지 않는 파일을 참조하지 않는다.
- 문서는 동작·운영, 구조·규칙, 변경 기록의 역할을 구분하고 중복 설명 대신 원본을 링크한다.
- 프레임워크 동작을 추측으로 단정하지 않는다. 코드가 의존하는 동작은 필요하면 작은 실험이나 회귀 테스트로 확인한다.
- 완료 보고에는 변경 내용과 검증 결과를 쓰고, 미실행 검사와 남은 위험을 명시한다.
